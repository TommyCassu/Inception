# User Documentation

## 1. What this stack provides

Three services running in three separate containers:

| Service | What it does | Reachable from |
|---|---|---|
| **NGINX** | The web server. Handles HTTPS and is the only way in. | on port 443 |
| **WordPress** | The website itself, running on php-fpm. | NGINX only |
| **MariaDB** | The database | WordPress only |

## 2. Before the first launch

Two things must be set up once on the machine.

The domain name :

`tcassu.42.fr` it has to be mapped to your own machine:

```bash
echo "127.0.0.1 tcassu.42.fr" | sudo tee -a /etc/hosts
```

Check it worked:

```bash
getent hosts tcassu.42.fr        # → 127.0.0.1  tcassu.42.fr
```

Without this line, **nothing** at `https://tcassu.42.fr` will load.

### The credentials files

The project needs `srcs/.env` and the `secrets/` folder to exist. See
[DEV_DOC.md §3](DEV_DOC.md#3-environment-setup-from-scratch) if you are setting the
project up from a fresh clone.

## 3. Start and stop

All commands are run from the root of the repository.

| I want to… | Command |
|---|---|
| **Start everything** | `make` |
| **Stop everything** | `make down` |
| Stop without removing the containers | `make stop` |
| Start them again | `make start` |
| Restart from scratch (keeps the data) | `make re` |
| See what is running | `make ps` |
| Watch the logs live | `make logs` (Ctrl-C to quit) |


⚠️ **`make fclean` deletes everything**, including the database and the website files.

## 4. Access the website

### The site

Open https://tcassu.42.fr in your browser.

Your browser will show a security warning — this is expected. The certificate is
self-signed (generated by the project itself).

### The administration panel

Open **https://tcassu.42.fr/wp-admin** and log in with the administrator account.

| Account | Login | Role | Can do |
|---|---|---|---|
| Administrator | `tcassu` | administrator | Everything: settings, users, themes, plugins |
| Second user | `toto` | editor | Write, edit and publish content — no settings access |

---

## 5. Where the credentials live

Passwords are **never** stored in the code or in the repository.

### Non-sensitive settings — `srcs/.env`

Names, titles, emails, the domain. No passwords.

```bash
cat srcs/.env
```

### Passwords — the `secrets/` folder

One file per password, containing only the value:

| File | Password for |
|---|---|
| `secrets/db_root_password.txt` | the database root account |
| `secrets/db_password.txt` | the database user WordPress connects with |
| `secrets/wp_admin_password.txt` | the WordPress administrator (`tcassu`) |
| `secrets/wp_sc_usr_password.txt` | the second WordPress user (`toto`) |

```bash
cat secrets/wp_admin_password.txt
```

**REMEMBER !** Never commit `srcs/.env` or `secrets/` to git. Both are listed in `.gitignore`, but
a file that was already committed once stays tracked until it is explicitly removed.

## 6. Check that everything works

### Quick check

```bash
make ps
```

The three containers (`mariadb`, `wordpress`, `nginx`) must all show **Up**.

### The website answers

```bash
curl -kI https://tcassu.42.fr        # → HTTP/1.1 200 OK
```

### HTTP is properly closed

```bash
curl -I http://tcassu.42.fr          # → connection refused (expected)
```

### The database is alive and populated

```bash
docker exec -it mariadb mysql -u toto -p -e "SHOW DATABASES;"
```

Enter the password from `secrets/db_password.txt`. You should see `wpdatabase`.

### WordPress is installed

```bash
docker exec wordpress wp core is-installed --path=/var/www/html --allow-root && echo OK
```

### Read the logs

```bash
make logs                            # all services
docker logs nginx                    # one service
```
